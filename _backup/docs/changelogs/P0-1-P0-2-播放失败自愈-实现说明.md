# P0-1 自动换源 + P0-2 网络重试（播放失败自愈）

> 对应《优化建议-下一阶段路线图》的 P0 首项："让 App 不坏"。
> 取链层（`Aggregator.audioWithFallbackNetwork`）此前已做多源顺序回退，真正的缺口在**播放层**：`PlayerCore.onError` 一旦 `MediaPlayer` 真正出错就直接 `cb.onError` 放弃。本改动在原生播放层补一个**自愈状态机**，仅在彻底救不活时才 `cb.onError`（保留现有前端"自动停止"行为）。

## 改动文件

| 文件 | 改动 |
| --- | --- |
| `src/com/tingshu/app/player/PlayerCore.java` | 新增自愈状态机 + `HealListener` 接口 + 进度落盘修正 |
| `src/com/tingshu/app/source/Aggregator.java` | `audioWithFallbackNetwork` 增加"跳过已失败源"重载 |
| `src/com/tingshu/app/MainActivity.java` | 接入 `HealListener`，换源时刷新前端书源标签 |
| `assets/www/app.js` | 新增 `window.onSourceSwitched` / `window.onPlayRetry` 钩子 |

## 自愈逻辑（PlayerCore.handleError）

1. **先落盘进度**：用出错瞬间保存的位置（`lastCurSec`，由每秒 tick 维护）落库，而不是 `curSec()`——出错态下 `MediaPlayer.getCurrentPosition()` 可能抛异常返回 0，会把续播位置覆盖成 0。
2. **网络类错误**（`MEDIA_ERROR_IO` / `MEDIA_ERROR_TIMED_OUT` / `SERVER_DIED`）：同一直链、原位续播，**渐增间隔 1s / 2s / 4s 重试最多 3 次**（用保存的 `lastHeaders` 原样复用 Referer 等头）。
3. **其它错误**（格式不支持 / 不明失败，多半是直链 403 或失效）：按 `Book.variants / sources` 顺序**自动换到下一个可用源**续播。`switchSource` 先把当前失败源加入跳过列表、剔除该集取链缓存，再在后台线程取新源直链，取回后带保存进度在主线程起播。
4. **网络重试耗尽**也会落到换源分支（双保险）。
5. **所有源都失败**才 `cb.onError`，由 `MainActivity.onError` → `window.onPlayError` 走既有"自动停止"逻辑。
6. **代际保护**（`healGen`）：用户切集 / 停止 / 重新起播会让 `healGen` 自增，过期的延迟重试与换源任务据此作废，避免"幽灵续播"。

## 前端反馈

- 自动换源成功：`HealListener.onHeal(1,…)` → `window.onSourceSwitched({source, sourceName})`，刷新播放条/全屏页右上角"书源胶囊"并轻提示。
- 网络重试：`HealListener.onHeal(0,…)` → `window.onPlayRetry()`，轻提示"网络波动，正在自动重试…"。
- 未设置 `HealListener` 时自愈静默进行。


## 自测建议

1. 找一个会偶发 403 / 直链过期的源，播到该集，观察是否自动换源且书源标签更新、进度不丢。
2. 弱网环境播一路，观察"网络波动，正在自动重试…"提示与重试后是否恢复。
3. 单源书（无 variants）播到死链，确认最终走到前端"自动停止"而非无限重试。
4. 自愈过程中手动切集 / 停止，确认不会"幽灵续播"到旧集。

## 已知边界

- 换源/重试期间播放图标仍显示"在播"、进度冻结（不闪动），属预期，避免 UI 抖动。
- 原生自愈失败后，前端仍保留其原有的"首次失败 800ms 后整链路重取一次"自救（最多 1 次），二者叠加不会死循环。
