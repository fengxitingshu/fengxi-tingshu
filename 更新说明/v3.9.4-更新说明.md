# v3.9.4 更新说明

> ⚠️ **这是紧急修复版，请务必从 v3.9.3 升级上来。** v3.9.3 存在**一打开就闪退**的严重问题，本版已彻底修复。

## 1. 启动闪退（严重，必修）

**现象**：v3.9.3 装上后**根本打不开**——点图标一闪就回到桌面，连首页都进不去。

**根因**：Android 对**前台服务通知的小图标**有硬性约束——小图标资源必须属于**本应用自己的包**。v3.9.3 在改通知栏时，把播放服务里的小图标写成了系统框架自带的 `android.R.drawable.ic_media_play`（包 ID `0x01`）。系统在 `startForeground()` 时校验资源归属，发现"不属于本包"直接抛 `Resources$NotFoundException`，进程当场崩溃。

反编译比对 dex 常量可以清楚看到这次回归：

| 版本 | 通知小图标常量 | 结果 |
|------|----------------|------|
| v3.9.2 | `0x7f020000` = `R.drawable.ic_notif`（本包） | ✅ 正常 |
| v3.9.3 | `0x1080024` = `android.R.drawable.ic_media_play`（框架） | ❌ 闪退 |
| **v3.9.4** | `0x7f020000` = `R.drawable.ic_notif`（本包） | ✅ 修复 |

**修复范围**（全项目共 4 处小图标 + 1 处桌面小组件）：

- `PlayerService.java`：3 处 `setSmallIcon(android.R.drawable.ic_media_play)` → `setSmallIcon(R.drawable.ic_notif)`
- `FloatBallService.java`：1 处前台通知小图标同上修正
- `PlayerWidgetProvider.java`：桌面小组件的播放/暂停图标从框架资源改为本包资源（`R.drawable.ic_notif_play` / `R.drawable.ic_notif_pause`）——**RemoteViews 是由桌面进程 inflate 的，同样不能用框架资源**，否则小组件按钮图标会失效。

**验证**：新版 dex 中"框架 drawable 常量出现次数 = **0**"，4 处 `setSmallIcon` 全部指向 `0x7F020000`。

> 注：`FloatBallService` 里对**自己进程内 ImageView** 调用的 `setImageResource(android.R.drawable.ic_media_play)` 是合法的，保留未动。

## 2. 书源管理 →「批量管理」里删除不生效

**现象**：进「书源管理 → 选中分组 → 批量管理」，勾上若干书源点删除，**毫无反应**，一条都没删掉。

**根因**：`app.js` 文件末尾残留着一段 **v3.7.14 时代的兼容占位代码**。这段代码位于真实实现**之后**，把 `ui.srcSelDelete`（以及全选 / 反选）重新赋值为空函数。JS 中后定义的赋值会**静默覆盖**前面的真实实现，于是点删除调到的其实是空壳函数——所以"看起来点了、实际什么都没发生"。

**修复**：删除占位块里对 `srcSelDelete` / `srcSelAll` / `srcSelInvert` 的空实现覆盖，只保留真正需要的空壳（`enterSrcMulti` / `exitSrcMulti` / `toggleSrcSel` / `doBatchDeleteSrc`），并在原处留下醒目注释：

```js
// ⚠️ 这里**绝不能再写** srcSelAll / srcSelInvert / srcSelDelete 的空实现 ——
// 本块在文件里位于真实实现之后，赋值会把真函数覆盖成空壳，
// 表现就是「批量管理里勾选后点删除毫无反应」（v3.9.3 的线上问题）。
```

**顺带修的关联问题**：

- **批量删除计数清理**：删除后同时清掉 `App._batchDel` 和 `App._bulkDel` 两个计数器（原来只清一个，残留计数会让后续操作状态错乱）。
- **自定义源分组隐藏删除按钮**：批量工具栏对 `builtin`（内置）和 `custom`（自定义）两个分组不再显示"删除"按钮——这两类书源本就不该被批量整组删掉。

## 3. 清理回放恢复遗留的重复代码

上一版（v3.9.3）的产物里混进了若干**重复代码块**，属于此前一次灾难性 `rm -rf` 后回放恢复时留下的脏数据。它们不是本次崩溃的直接原因，但会让文件虚胖、并造成"后面的旧实现覆盖前面新修复"的隐性 bug：

| 重复内容 | 影响 | 处理 |
|----------|------|------|
| 旧版「自定义源管理页」整块（475 行，用 `card-bd` 容器） | 与新版 `cu-bd` 版并存，选择器混乱 | 删除旧块，保留新版 |
| 旧版 `window.onListenedMarks`（走 `renderDetail()`） | **覆盖** v3.9.3 的 `paintChapMarks()` 修复 → 章节列表滑动卡顿、弹回顶部**复发** | 删除旧块 |
| 重复的 `pyReload` / `pySelfTest` / `onPySelfTest` | Py 源自检功能行为不确定 | 删除重复定义 |
| v3.9.3「首页本地书」钩子被插入到两处 | 首页本地书入口可能失效 | 合并回单一 `window.onLocalBooks` |

**修复后**：`app.js` 从 921KB 瘦身回 **408,662 字节 / 8,895 行**，`node --check` 语法校验通过，全文已无 30 行以上的重复代码块。

## 升级提示

1. **本版必升**：v3.9.3 打不开，直接覆盖安装 v3.9.4 即可（版本号 56 > 55，同签名，数据保留）。
2. **小组件**：若你之前加过桌面小组件，升级后建议移除再重新添加一次，确保图标/按钮走新资源。
3. 旧备份包可直接恢复；py 源升级后杀进程重进一次即可。
