# 枫兮听书 v4.21.32 更新说明

**versionCode 224 · 2026-11-07**

## 本次解决：App 退出后桌面小组件不能「直接播放」

之前的行为：App 彻底退出（从最近任务划掉 / 一键清理 / 进程被系统回收）后，
点桌面小组件的播放键只会把界面拉起来，还得再点一次才能出声。原因是播放引擎
`PlayerCore` 一直由 `MainActivity` 持有，界面/进程一没，播放器就没了；
后台服务只负责通知栏和锁屏，自己不会播放。

## 方案 B：播放引擎搬进后台服务

| 场景 | 之前 | 现在 |
|---|---|---|
| App 退出后点小组件播放 | 弹出界面，需再点一次 | **直接出声，全程不弹界面** |
| 小组件/通知栏/锁屏/蓝牙控制 | 冷启动后全部失效 | 全部照常可用 |
| 小组件先起播、之后点封面进 App | — | **无缝接管**，不中断、不重取链、不双声 |
| 退出界面但还在听 | 界面销毁 → 播放停止 | 核心交回服务，**后台继续播** |
| 主动点「停止」 | — | 清掉会话，不会被小组件意外续上 |

### 实现要点

1. **会话落盘**（新增 `ResumeSession`）：书（含换源用的 variants）、整张章节表、
   集下标、集内进度、实际源 id、章节定位串写进独立 SharedPreferences。
   - **不存音频直链**：百度 dlink 有时效，存了反而会播死链。恢复时一律重新取链。
   - 起播 / 切集 / 每 5 秒进度都写；主动停止时清除。

2. **服务暗核心**（`PlayerService`）：界面不在时（`CTL == null`），控制命令自动落到
   `HEADLESS_CTL`，服务自己持有一个 `PlayerCore`，从会话快照恢复 →
   `Aggregator.audioWithFallback` 纯 Java 重新取链（含网盘 `PanResolver`）→ 直接起播。
   - 可行性前提已核实：进程冷启动时 `App.onCreate()` 会先重建 Settings、网盘 Cookie、
     书源表、数据库；取链链路不依赖 WebView / Activity。
   - 暗核心的回调只更新通知栏 + 桌面小组件 + 会话，**不碰 WebView**。
   - 自动连播、播放模式（顺序/单曲/列表循环/随机）、定时关闭在无界面时同样生效。

3. **接管 / 交回**：
   - `MainActivity.onCreate` 调 `takeHeadless(this)`，有暗核心就复用同一个播放器，
     只换绑 Callback / HealListener / 倍速 / 定时钩子。
   - `MainActivity.onDestroy` 若仍在播则 `giveBack(core)` 交回服务，否则才 release。

4. **保护既有链路**：App 在前台时 `ctl()` 仍返回原来的 `MainActivity`，
   所有播放、取链、百度网盘「转存 → filemetas 取链 → 缓存中继」路径**一行未改**。

### 测试步骤

1. 覆盖安装后，随便播一集（让它出声）。
2. 从最近任务**划掉 App**（或用一键清理），确认通知栏也消失。
3. 直接点桌面小组件的**播放键** → 应在 1~3 秒内出声，且**不会弹出 App 界面**。
4. 之后点小组件**封面/书名**进 App → 播放不中断、进度连续。
5. 点通知栏或小组件的**停止** → 再划掉 App → 点播放键应打开界面选书（会话已清）。

> 若冷启动后点播放没反应，去「关于 → 问题诊断 → 播放链路」看 `[headless]` 开头的日志：
> `服务自持播放核心已就绪` / `冷恢复《…》第 N 集` / `重新取链` / `已起播（无界面）`，
> 哪一步没出现就定位到哪一环。
