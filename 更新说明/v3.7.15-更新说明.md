## 一、★ 修了一个「装不上」的严重问题

**上一版 v3.7.14 的安装包是未签名的，装不上。**

你反馈新版本无法安装，排查结果：

```
$ apksigner verify release/枫兮听书-v3.7.14.apk
DOES NOT VERIFY
ERROR: Missing META-INF/MANIFEST.MF
```

对比一下就很清楚了：

| 文件 | 大小 | 签名 |
|---|---|---|
| `release/枫兮听书-v3.7.14.apk` | 18,316,488 | ❌ 未签名 |
| `out/aligned.apk`（签名**前**的中间产物） | 18,316,488 | ❌ 未签名 |
| `TingShu.apk`（签名**后**的正确成品） | 18,329,872 | ✅ 已签名 |

**字节数完全一致** —— 打包时把签名前的 `aligned.apk` 当成成品发了出去，手机自然报「解析包错误」。

**防复发**：构建脚本和发布脚本都加了**签名硬闸门**，签不过名直接判构建失败：

- `build.sh` 第 9 步：`apksigner verify` 不通过 → `exit 1`；再比对成品 ≠ `aligned.apk`；再确认 `META-INF/MANIFEST.MF` 存在。
- `发布Release.sh`：上传前先验签，没签名一律拒绝发布。

以后这类问题不可能再流到用户手上。

## 四、★ 新增：进度条可点击跳转

原来进度条只是**只读**显示，现在能调进度了。

**技术限制说明**：Android 的桌面小组件（RemoteViews）**不支持 SeekBar** —— `AbsSeekBar` 不在允许的控件白名单里，做不出真正的「拖」。所以采用系统常用的替代方案：

> 进度条上盖一层 **20 格透明点击区**，点第 i 格 = 跳到 `(i+0.5)/20` 的位置。
> 粒度 **5%**。听书场景一章普遍 20~60 分钟，一格约 1~3 分钟，足够用。

配套改动：

- 进度条左侧显示**当前时间**、右侧显示**总时长**（原来是合并成一行的 `12:22 / 38:00`）；
- 新增 `PlayerService.ACT_SEEK` action，带 `sec` extras 精确跳转，复用已有的 `svcSeek()` → MediaSession 同步链路；
- 20 格用了 **20 个不同 requestCode**（100+i）。这是必须的坑：PendingIntent 判定「是否同一个」**不看 extras**，requestCode 相同的话 `FLAG_UPDATE_CURRENT` 会让最后一格覆盖全部，点哪都跳同一个位置。

## 五、★ 本版追加修复三项（v3.7.15-fix）

你反馈的三件事：**概率闪退、小组件一片空白、之前的 JS 源似乎没有了**。逐一定位：

### 1. 小组件一片空白 —— 根因找到并修复

**根因**：上一版给进度条加"可点击"时，我在进度条上盖了 20 个点击分区，用的是普通 `<View>` 标签。

Android 的桌面小组件（RemoteViews）**只允许特定几种控件**，白名单里有 `LinearLayout` / `FrameLayout` / `RelativeLayout` / `ImageView` / `TextView` / `ProgressBar` / `Button` 等，**但没有普通 `View`**。桌面启动器 inflate 布局时遇到 `View` 直接失败，**整块小组件就渲染成空白**。

对照实验（很能说明问题）：

| 版本 | 布局里的 `<View>` 数量 | 桌面表现 |
|---|---|---|
| v3.7.14 | 0 个 | 正常显示 |
| v3.7.15（坏） | **20 个**（进度条点击分区） | **一片空白** |
| v3.7.15-fix | 0 个（全换成 `ImageView`） | 正常 |

**修复**：20 个 `<View>` 全部替换为 `<ImageView>`（透明、无图，只用来接点击），外观与行为完全不变。

**防复发**：回归脚本加了一条**白名单断言** —— 把布局里出现的所有控件标签抽出来逐个比对白名单，出现任何非法控件立即构建失败；并且用 `aapt2` 反解**打包后的**布局做二次复核（防止"源码改了但没进包"）。

### 2. 之前能用的 JS 源突然不见了

原来 JS 插件加载失败是**静默吞掉**的 —— `catch (Throwable ignored) {}`，失败了既不报错也不记录，用户只看到"源没了"，我这边也拿不到任何线索。

现在做了三件事：

- **不再静默**：加载失败/异常都写进运行期记录（含包名、失败在哪一步、异常类名与消息）；
- **成功也记数**：记录每个包"加载出几个源"，方便比对数量骤减；
- **新增「源加载诊断」页**（关于页 → 问题诊断）：一眼看清每个 JS 插件包的
  *目录是否还在 / manifest 是否完整 / 登记了几个源 / 实际存活几个 / 现场重试加载报什么错*。

**最可能的原因**（诊断页会直接告诉你是哪种）：本版换了签名，**必须先卸载旧版才能装**，而卸载会清空应用私有目录 —— **JS 插件包就存在那里**（`filesDir/plugins` 与 `filesDir/js_plugins`）。所以重装后源列表会回到"只有你重新导入过的"状态。

> 解决办法：在「书源管理」里重新导入一次 JS 插件包即可，之前的链接还能用。
> 如果诊断页显示"包在、但加载失败"，把那一页截图发我，错误原因就在上面。

### 3. 概率闪退 —— 先装上"黑匣子"

闪退最难的是**没有堆栈**。手工构建的包没有崩溃上报，以往只能靠猜。

现在加了崩溃日志落盘：任何未捕获异常都会把**完整堆栈 + 版本号 + 机型 + Android 版本**写到 `filesDir/crash/crash-<时间戳>.log`（保留最近 5 份）。

**怎么看**：关于页 → 问题诊断 → **崩溃日志**，一键复制。**下次再闪退，把这个页面截图或复制发我，就能精确定位了。**

> 说明：本次只加了"记录"能力，没有改任何业务逻辑去"猜"着修 —— 盲改反而可能引入新问题。等拿到真实堆栈再对症下药。
