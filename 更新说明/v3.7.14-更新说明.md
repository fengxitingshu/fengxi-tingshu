## 本版修复

### 1. 源管理：取消长按多选，只保留长按菜单

**现象**：长按一行会同时做两件事——勾选该行进入多选模式，并弹出菜单。两个动作叠在一起，用户只想改个名字却进了多选，想多选又总被菜单挡住。

**修复**：**多选功能整体下掉**，长按只弹菜单。

- 长按 480ms → 只在按下的位置弹出该行菜单，不再勾选、不再进多选
- 列表内所有勾选框（`.chk-src`）、底部多选操作条（`#srcMultiBar`，含计数 / 全选 / 反选 / 删除）全部移除
- 批量删除相关的 9 个内部函数改为空实现，避免残留调用报错
- 每行右侧的启用开关（`.sw`）单独排除在手势之外，点开关不会误触发长按

现在源管理是**一种交互一套逻辑**：短按开关启停、长按弹菜单，菜单里包含 启用/停用、测试连通性、重命名、删除此源。

### 2. 测试连通性无效（真根因修复）

**现象**：点「测试连通性」永远返回「无响应」，无论源好坏。

**真根因**：native 端 `BridgeSource.testCustom` 的判断顺序是 `JsonSource` → `isBuiltin` → 其它兜底。**Python 源（`PySourceAdapter`）既不是 JsonSource 也不 isBuiltin**，于是掉进最后的 jar 兜底分支，里面调 `cfgBaseOf(s)` 去**反射取一个根本不存在的 `BASE` 静态字段**，回落到默认值 `https://example.com` —— 探测一个不存在的域名，当然永远无响应。结论完全不可信。

**修复**：

- 判断顺序改为 `null` → `isBuiltin`（**前置**，原来排在 JsonSource 之后会被误判）→ `JsonSource` → **新增 `PySourceAdapter` 分支** → jar / JS 兜底
- Python 源分支：先查 Python 运行时是否就绪 → 再查 `canSearch()` → 用真实关键词 `search("评书", 1)` 实测搜索，按命中数给结论
- 删除了 `cfgBaseOf` 这个靠反射猜字段的无效兜底，新增 `testByBrowse(Source)`：对不支持搜索的源，改用 `BrowsableSource.categories()` 判可达

**现在的结论**：`连通正常，搜索命中 N 条` / `站点已响应，但没搜出结果（可能被限流或关键词无货）` / `Python 运行时未就绪，请稍后重试`，不再有笼统的「无响应」。

### 3. 桌面小组件：按钮点不动 + 点哪都跳回 App

这两个毛病是**同一个根因**。

**真根因**：`PlayerWidgetProvider.build()` 里给 `wgRoot` 绑了打开 App 的 `PendingIntent`。而 `wgRoot` 是**整块面板的根布局**，它的点击区域覆盖了所有子 View —— 三个控制按钮的点击全被它吞掉。所以「按钮没反应」和「点哪都回软件」是同一件事的两个表现。

**修复**：

- 彻底移除 `wgRoot` 上的点击绑定
- 三个按钮各自独立绑定：上一集 / 播放暂停 / 下一集
- 只有**封面**和**书名信息区**两块绑打开 App（各自独立 View，不再互相吞点击）

**第二层根因**：按钮绑的是 `PendingIntent.getBroadcast`，然后在 `onReceive` 里 `startForegroundService`。**Android 8+ 禁止从后台广播启动前台服务**，所以即使点击送达了，服务也起不来。

**修复**：改用 `PendingIntent.getService`，直接把命令投递给 `PlayerService`，绕过广播限制。

**第三层根因**：`PlayerService.onStartCommand` 里判断 `if (a != null && CTL != null)`，当 CTL 为 null（进程被回收后系统拉起）时命令**被静默丢弃**，用户点了完全没反应。

**修复**：改为把控制命令缓存下来，等 CTL 绑定就绪后补执行。

### 4. 桌面小组件：透明主题 + iQOO 液态玻璃适配

**难点**：AppWidget 运行在桌面宿主进程里，**拿不到「后面的壁纸」这张图**，所以系统原生的 `BLUR_BEHIND` 模糊在小组件上不可用。

**做法**：用 `layer-list` 三层叠加去**近似**液态玻璃观感：

| 层 | 内容 | 作用 |
|---|---|---|
| 底 | `#9E1A1A22` 半透明深色 | 保证任何壁纸上文字都可读 |
| 中 | 白渐变 `#3DFFFFFF → #14FFFFFF → #08FFFFFF`（angle=270） | 顶部高光的「玻璃反光」 |
| 顶 | 1dp 描边 `#4DFFFFFF` + 24dp 大圆角 | 玻璃边缘折射高光 |

按钮 `wg_btn_bg.xml`、封面 `wg_cover_bg.xml` 同样改为半透明 + 细白边，整体一套玻璃语言。进度条也换成半透明白底 + 纯白进度。

在 iQOO（OriginOS）的液态玻璃桌面上，这套半透明叠加会**透出桌面本身的模糊效果**，视觉上与系统组件同一语系。

### 5. 桌面小组件：增加封面显示

**真根因**：封面是在 `PlayerService.loadCover()` 里**异步下载**的，而 `syncWidget()` 发生在 `onStateChanged` 那一刻 —— 图还没下回来，`lastCoverBmp()` 返回 null，于是 `WidgetState.cover` 永远是空的。

**修复**：封面下载完成后**额外触发一次 `syncWidget()`**，让封面补上。同时新增 `wgCoverTap` 层，封面显示出来后点击它可直达播放页。

### 6. 桌面小组件：显示当前播放信息 + 超长跑马灯

**新增信息行**：

- 主标题：书名
- 副标题：主播名 · 当前集 / 总集数
- 时间行：已播时长 / 总时长
- 进度条：实时百分比

**跑马灯有个坑**：RemoteViews 里 `TextView` 要在代码中 `setSelected(true)` 才会滚动，光在 XML 写 `ellipsize="marquee"` + `singleLine` 是不动的。已补上：

```java
v.setBoolean(R.id.wgTitle, "setSelected", true);
v.setBoolean(R.id.wgSub,   "setSelected", true);
```

另外，本版给三个按钮加了**空闲态淡化**（没有播放内容时透明度降到 42%），并给进度条加了 API 31 守卫（`setFloat` 是 API 31+ 接口，低版本跳过，避免崩溃）。

### 7. 自动连播时小组件停在上集信息

**真根因**：`onStarted` 回调里没调 `syncWidget()`，只有 `onStateChanged`（播放/暂停切换）才同步。自动播下一集时 playing 一直是 true，状态没变化，**回调不触发**，小组件就一直显示上一集。

**修复**：`onStarted` 里补一次 `syncWidget()`。

## 安装说明

1. 卸载旧版或直接覆盖安装（包名一致，签名一致，可直接覆盖）
2. 若旧版为更早的签名版本，需先卸载再安装
3. **小组件更新提示**：本版改动较大，升级后如果桌面小组件显示还是旧样子，请**长按小组件 → 移除 → 重新添加一次**（Android 不会自动刷新已存在的小组件布局）
4. 首次启动后如有 Python 源，稍等片刻等待源登记完成
