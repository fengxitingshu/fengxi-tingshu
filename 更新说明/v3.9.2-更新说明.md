# 枫兮听书 v3.9.2 更新说明

> 主题：v3.9.1 三个"改了还没好"的问题，逐个挖到真正根因后修复。
> 共 3 项，全部来自实际使用反馈（机型 iQOO 15 / originOS 7 / Android 16）。

---

## 一、小组件白卡（v3.9.1 未除根，本版根治）

**现象**：v3.9.1 装上后小组件**仍然是白卡**（移除重加也一样）。

**根因（这次是挖到 dex 里对比出来的）**：v3.9.1 只换了布局（零自绘引用），
但没动 `build()` 里的 **RemoteViews 动作**。把 v3.8.5（在这台机上好用的
最后一版）和 v3.9.0/v3.9.1 的 dex 反编译对比后发现：3.9.0 和 3.9.1 的
`build()` 用了三类 **v3.8.5 从来没用过**的动作——

- `setViewVisibility`（12 处，显隐封面占位/角标/状态点）
- `setTextColor`（状态点变色）
- `setFloat`（`setAlpha` 给四键置灰，API 31+，本机必执行）

在 originOS 桌面上，这些动作在 **apply 阶段**抛异常，整包 RemoteViews 被
丢弃，桌面回落到默认错误视图——就是那张白卡 + 转圈。布局再怎么"零解析"
都没用，凶手在动作集里。

**本版做法（动作集回退到 v3.8.5 实测可用的六类）**：

- 只用：`setTextViewText` / `setImageViewBitmap` / `setImageViewResource` /
  `setInt("setBackgroundColor")` / `setBoolean("setSelected")` /
  `setOnClickPendingIntent`
- **禁用**：`setViewVisibility` / `setTextColor` / `setFloat` / `setProgressBar`
- 封面占位符（♪）改为**常驻底层**：封面图来之前显示 ♪，图一到
  （centerCrop 铺满）自然盖住它——不需要切可见性
- 倍速/定时角标显隐改为「空文案 + `setInt` 透明背景」
- 状态点固定暖色，隐藏时文案置空；四键置灰动画整个去掉
- 恢复了 v3.8.5 同款的**分段诊断日志**（build 每段失败都会写进
  「设置 → 小组件诊断」），再出问题能直接看到是哪段

> ⚠️ 旧小组件仍需**移除后重新添加**一次（桌面缓存的是旧 RemoteViews）。

## 二、备份恢复提示"文件损坏"（每个包都恢复不了）

**现象**：拿自己刚导出的 `.fxbak` 恢复，提示"备份包内容校验失败
（文件可能已损坏）"，换哪个包都一样。

**根因**：校验和两侧口径不一致——

- 打包侧算的是 `contentChecksum(blobs)`，而 `blobs` 里**没有**
  `manifest.json`（manifest 是写 zip 时的独立参数）
- 恢复侧 `readZip` 会把 `manifest.json` 也放进 `p.blobs`（它也是文本条目），
  `validate()` 直接拿 `p.blobs` 算摘要

两边永远差一个 `manifest.json` 的摘要 → **每个合法备份包都校验失败**。
（这和选文件权限无关，是纯粹的算法口径 bug，所以 v3.9.1 加了持久授权
也治不好。）

**本版做法**：恢复侧算校验和前先摘掉 `manifest.json`，与打包侧口径一致。
已有的备份包无需重新导出，直接就能恢复。

## 三、py 源只有封面、没有章节

**现象**：py 源能搜到书、列表有封面，点进详情却**没有章节表**。

**根因**：调用约定不匹配。TVBox/DSPlayer 引擎里 `detailContent` 收的是
**列表**（源里清一色 `ids[0]` 取下一条），而我们的 Python 运行时一直传
**字符串**——`ids[0]` 只会拿到 id 的第一个字符，源拿这个错误地址去请求，
返回空 list（或抛异常），Java 侧就得到"封面有、章节空"。

**本版做法**（`fxts_runtime.py`，app.imy 已重新打包、build.json 哈希已同步）：

- `detailContent`：先按 TVBox 约定传 `[ids]`；返回空列表或抛异常时，
  再按字符串约定传一次。两种都没货才回传真实空列表，不假成功
- `playerContent` 的 `vipFlags` 同样做了双约定兼容（布尔 ↔ 列表）
- 已用三种模拟源（列表约定/字符串约定/双失败）本地验证通过

> 说明：Python 运行时在首次启动时会解压到 App 私有目录。如果升级后
> py 源行为没变化，杀掉 App 重进一次；仍不行就清除 App 数据后重新导入
> py 源（解压缓存会按新哈希自动刷新，正常情况下无需手动处理）。
