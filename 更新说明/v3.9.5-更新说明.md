## 1. 为什么 v3.9.4 还是闪退？—— 重新定位

v3.9.4 我判断是「通知小图标用了系统框架资源」导致，但你把新包装上后**依旧闪退**，且**没有任何崩溃日志**。这说明：

- 崩溃发生在**比通知更早**的阶段 —— 甚至早到「崩溃处理器还没挂上」，所以日志目录里什么都没有；
- 我把 v3.9.4 的安装包和你确认可用的 v3.9.2 做了**逐文件比对**：dex 几乎完全一致（只差 8 个类，全是新增小组件图标的资源 ID 位移）、资源表一致、原生库一致、签名一致、清单一致。**单靠静态分析已经找不到差异了。**

结论：这次的崩溃很可能是 **App 启动时某一个初始化步骤抛异常**（某个源加载失败、数据库打开失败、Python 宿主初始化失败等），而这个异常**直接把进程带走了**，表现就是「点图标闪一下就没」。

## 2. 本版的核心改动：初始化全隔离 + 日志必留

### 2.1 每一个初始化步骤单独 try-catch

`App.onCreate()` 里原本是一串**裸调用**：

```java
Settings.init(this);
Net.loadCookies(...);
PlayState.init(this);
SourceRegistry.registerAll();   // ← 磁盘 / 反射 / 插件加载
...PythonHost...
CacheManager.init(this);
DownloadManager.init(this);
Db.init(this);                  // ← SQLite 打开
```

**这里任何一步抛异常，App 都当场死亡。** 现在改成：

```java
try { Settings.init(this); }        catch (Throwable t) { logInit("Settings", t); }
try { Net.loadCookies(...); }       catch (Throwable t) { logInit("Net", t); }
try { PlayState.init(this); }       catch (Throwable t) { logInit("PlayState", t); }
try { SourceRegistry.registerAll(); } catch (Throwable t) { logInit("SourceRegistry", t); }
try { ...PythonHost... }            catch (Throwable t) { logInit("PythonHost", t); }
try { CacheManager.init(this); }    catch (Throwable t) { logInit("CacheManager", t); }
try { DownloadManager.init(this); } catch (Throwable t) { logInit("DownloadManager", t); }
try { Db.init(this); }              catch (Throwable t) { logInit("Db", t); }
```

效果：**某一步炸了，只让那部分功能不可用，首页照常打得开。** 「能进去用，个别源不行」永远好过「完全打不开」。

### 2.2 崩溃日志现在「一定会留下」

- **提前挂载**：崩溃处理器从 `App.onCreate()` 的中段，提到**第一行**执行。原来它挂在初始化中间，一旦初始化崩了，处理器还没生效 —— 这就是你找不到日志的原因。
- **双写 + 免权限路径**：除原来的私有目录外，**再写一份到外部目录**：
  ```
  /sdcard/Android/data/com.tingshu.app/files/crash.log
  ```
  这个路径是应用专属沙箱，**不需要任何权限**，用手机自带的「文件管理」就能进去找、直接发出来，不必连电脑抓 logcat。
- **初始化失败也记录**：被隔离掉的初始化异常，会以「**初始化失败（已隔离，未闪退）**」的形式写进同一份日志，写明是**哪个步骤**失败 + 完整堆栈。
