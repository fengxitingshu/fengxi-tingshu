## 一句话总结

你截图里的报错 `NoClassDefFoundError: org.mozilla.javascript.W2` 直接把根因指出来了 —— **打包混淆把 JS 引擎内部一个「按名字反射加载」的类改成了 `W2`**，运行时按原名找不到，整个 JS 引擎就起不来。**JS 插件装不进去**、**小组件又变空白**，都是它引起的。

---

## 一、为什么 JS 插件包一直装不进去

### 你截图里的报错

```
导入完成：失败 1 个
插件包没有装载出可用的书源，请确认包内有 manifest.json 且声明了 scripts。
JS 插件包：plugins.zip
加载异常：NoClassDefFoundError: org.mozilla.javascript.W2
```

最后那行 `org.mozilla.javascript.W2` 是关键线索。

### 根因

打包时的混淆步骤会把类名换成 `a`、`b`、`W1`、`W2` 这种短名字来缩小体积。而 **JS 引擎（Rhino）内部有一处是用「写死的字符串名字」去找自己另一个类的**：

```java
Class.forName("org.mozilla.javascript.VMBridge")
```

混淆后这个类的真实名字变成了 `W2`：

```
原始名：org.mozilla.javascript.VMBridge
混淆后：org.mozilla.javascript.W2        ← 名字对不上了
```

于是运行时按 `VMBridge` 这个名字去找 → **找不到** → `NoClassDefFoundError` → **整个 JS 引擎初始化失败** → **任何 JS 插件包都装不进去**。

### 这解释了整条时间线

| 时间 | 现象 | 真相 |
| --- | --- | --- |
| 更早 | 「JS 源突然不见了」 | 其实就是这个，只是当时静默吞了错误看不到原因 |
| v3.7.15 | 加了诊断页，让失败**可见** | 但没找到根因 |
| 现在 | 报错直接打出 `W2` | 根因**终于暴露** |

> 我上次说「包没问题、链路没问题、引擎也没问题」——**包和链路确实没问题，我当时的离线测试是在电脑上跑的，而混淆只发生在打包环节**，所以那个测试恰好绕过了这个坑。这次是真实报错把问题钉死了。

### 修复

把 JS 引擎整体加入混淆保护名单（混淆它只能省几百 KB，收益远抵不上风险），并新增构建校验：**引擎关键类一旦被改名，构建直接失败**。

## 二、小组件为什么又变空白

同一个根因的连带后果。

JS 引擎类加载失败 → 每次加载插件/重建源都会抛异常 → **App 进程反复崩溃** → 小组件拿不到内容更新，就渲染成空白。

引擎修好后进程稳定，小组件随之恢复。

> **装好本版后，请长按桌面上那个空白小组件 → 移除 → 重新添加一次。**

---

## 三、两道构建闸门（防止再犯）

这已经是第三次栽在「混淆改名」上了（前两次是小组件的类）。现在打包流程里有两道硬校验，任何一道不过直接判构建失败：

| 闸门 | 检查什么 | 拦住的教训 |
| --- | --- | --- |
| **Manifest 组件保名闸门** | Manifest 声明的类名 == 混淆后真实类名 | 小组件 Provider / Receiver 被改名 |
| **反射类保名闸门** | JS 引擎关键类未被改名 | `VMBridge` 被改成 `W2` |

### 装好后建议做两件事

1. **重新导入一次 JS 插件包**（之前失败的那些包没有被记录，需要重装一次）
   → 源管理 → 导入源 → 选择本地文件 → 选你的 `plugins.zip`
   → 正常应提示「已装载插件包「ShunSources」 v2.1.0，共 19 个书源」

2. **小组件移除后重新添加**
   → 长按桌面空白小组件 → 移除 → 重新从小组件列表拖一个出来

### 如果还有问题

打开 **关于 → 问题诊断 → 源加载诊断** 截图发我，那里能看到每个插件包的目录状态、加载出几个源、失败报什么错。
