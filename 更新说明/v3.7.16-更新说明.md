## 一、桌面小组件五个症状：同一个根因

### 症状（你反馈的）

> 小组件不显示封面，不能控制播放暂停啥的，进度条也没反应，点击只能回到 App

### 根因：打包混淆把小组件的两个类改了名字

打包时有个「代码混淆」步骤会把人能看懂的名字换成 `a`、`b`、`c`，用来缩小体积、防止反编译。问题是：

- 系统加载小组件时，是**按 `AndroidManifest.xml` 里写的类名**去找类的
- manifest 里写的是 `com.tingshu.app.widget.PlayerWidgetProvider`
- 而混淆后这个类实际叫 `com.tingshu.app.widget.a`

**名字对不上 → 系统认为这个小组件根本不存在。**

我把上一版（v3.7.15）交付的安装包拆开验证了，`widget` 包下**真的只剩一个 `a`**：

```
旧包（v3.7.15）：com/tingshu/app/widget/a          ← 只有这个
新包（v3.7.16）：com/tingshu/app/widget/PlayerWidgetProvider
                com/tingshu/app/widget/WidgetClickReceiver
```

这一个原因，同时解释了你的**全部五个症状**：

| 你看到的 | 为什么 |
| --- | --- |
| 小组件一片空白 | 布局由 Provider 提供，Provider 找不到 → 没有任何内容 |
| 封面不显示 | 封面上屏也是走 Provider 的更新通道 |
| 播放暂停键没用 | 按钮的点击事件要投给它，找不到就静默丢弃 |
| 进度条点了没反应 | 同上 |
| 点哪都只能回到 App | 只有 `MainActivity` 在混淆保护名单里，**所以只有它还能响应** |

> 这也解释了为什么 v3.7.15 单独修「小组件空白」没修好 —— 当时定位到的是另一个问题（布局里用了系统不认的控件，那个也确实是问题并已修掉），但**混淆改名这个更底层的原因一直没被看见**，两个问题叠在一起。

### 修复

1. 把 `com.tingshu.app.widget.**` 加进混淆保护名单
2. **额外加了一道构建自动校验**：每次打包都会比对「`AndroidManifest.xml` 里声明的类名」和「混淆后的真实类名」，只要有一个对不上，**构建直接失败**，不可能再流到手上

## 二、小组件按钮「投递不到播放器」

### 根因：桌面是「另一个 App」

桌面（launcher）跟我们是**两个不同的 App**。它在替我们处理小组件点击时，系统会做一次安全检查：

> 这个目标组件，允许外部 App 访问吗？

而原来的两个目标都是「仅本 App 可用」（`exported="false"`）：

- `PlayerWidgetProvider`（小组件本体）
- `PlayerService`（播放服务）

于是桌面的点击请求**被系统静默丢掉** —— 不报错、不提示，就是什么都没发生。

### 修复

新增一个**专门对外接收点击的中间组件** `WidgetClickReceiver`（明确标记为允许外部访问），它只干一件事：收到点击 → 转交给播放服务。链路变成：

```
桌面点击 → WidgetClickReceiver（对外可访问）→ PlayerService（仅本 App，正常工作）
```

## 三、「更多」菜单和选集下拉菜单点了没反应

### 症状

> 播放界面更多里边的功能失效，选集里边的下拉菜单同样失效

### 根因：菜单自己把自己关掉了

这两个菜单用的是同一套代码。原来的「点别处自动关闭」是这么注册的：

```js
document.addEventListener('click', 关闭菜单, { once: true });
```

问题在于，这行代码是在**「打开菜单的那一次点击」里面**执行的。而这次点击事件还没结束、正在继续往外冒泡 —— 冒到最外层时，**立刻命中了刚刚注册的关闭监听**。

结果就是：**菜单在打开的那一瞬间就被拆掉了**，快到肉眼几乎看不见。

### 修复

改成：

1. 等这次点击**彻底结束之后**（下一个事件循环）才开始监听
2. 加一个 `closed` 标志防止重复关闭
3. 点事件落在菜单**自己内部**时，直接跳过不关

### 结论：与小组件同一个根因

我做了完整排查，把你这包 `plugins.zip`（ShunSources v2.1.0）**在本地用同一套引擎完整跑了一遍**：

```
1) 探测是不是 JS 插件包     → ✓ 是
2) 解包 7 个文件            → ✓ 成功（manifest.json + 6 个脚本）
3) 逐个执行 6 个脚本        → ✓ 全部通过（common/cms/sites/api/zblog/ximalaya）
4) 注册出的书源数           → 19 个
   （念音网、有听网、乐听吧、米听书、囧贼听书网、一夜幻听、听中国、
     爱听书、单田芳评书网、声音巴士、悦听吧、哔哩哔哩、博看有声、
```

**包本身没问题、导入链路没问题、加载引擎也没问题** —— 是混淆改名连带把这条链路弄坏了。现在已修复。

## 五、菜单超出屏幕 & 章节名被截断

### 修复 1：菜单不再跑出屏幕

- 宽度超过屏幕时**自动收窄**（最多占屏幕 82%）
- 菜单项文字过长的，改成**横向滑动查看**（以前直接被截断成「…」，根本看不到内容）
- 在屏幕**底部放不下时自动翻到上方**显示，不会被屏幕边缘切掉

### 修复 2：超长章节名改跑马灯

选集列表和详情页的超长章节名，以前会被截成 `第 001 集 三国演…`。现在**横向滚动显示完整名称**。

多列排布时自动关闭滚动 —— 格子本来就只有 1/3 屏宽，滚动反而更看不清。
